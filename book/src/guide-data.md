# ข้อมูลสุ่ม

```rust
# use rand::Rng;
# fn main() {
// get some random data:
let mut data = [0u8; 8];
rand::rng().fill_bytes(&mut data);
println!("{:?}", data)
# }
```

## ความสุ่มคืออะไร?

คำว่า **สุ่ม** หมายถึงอะไร? ในภาษาพูด คำนี้อาจหมายถึงแค่ *ไม่คาดคิด* หรือ *ไม่ทราบค่า* แต่เราจำเป็นต้องนิยามให้แม่นยำกว่านั้นเล็กน้อย Wikipedia ให้คำนิยามที่เฉพาะเจาะจงกว่าว่า:

> **ความสุ่ม (Randomness)** คือการไม่มีรูปแบบหรือไม่สามารถทำนายเหตุการณ์ได้

เราสามารถต่อยอดจากตรงนี้ได้: *การไม่มีรูปแบบ* บ่งบอกว่าไม่มีความ*เอนเอียง* กล่าวอีกนัยหนึ่งคือ ค่าที่เป็นไปได้ทั้งหมดมีโอกาสเท่ากัน

การจะเข้าใจว่า *ค่าสุ่ม* คืออะไร เรายังต้องมีบริบทว่า ค่าสุ่มของเรามาจากกลุ่มตัวเลขใด?

-   ตัวอย่างง่ายๆ ลองนึกถึงลูกเต๋า: มันมีค่า 1, 2, 3, 4, 5 และ
    6 และลูกเต๋าที่ไม่เอนเอียง (เที่ยงตรง) จะทำให้แต่ละตัวเลขมีโอกาสเท่ากัน
    ด้วยความน่าจะเป็น ⅙
-   ทีนี้ลองยกตัวอย่างที่ไร้สาระบ้าง: จำนวนนับ (1, 2, 3, ฯลฯ) ตัวเลขเหล่านี้
    ไม่มีขีดจำกัด ดังนั้นหากคุณขอจำนวนนับแบบสุ่มที่ไม่เอนเอียง
    1, 5, 1000, 1 ล้าน, 1 ล้านล้าน — ทั้งหมดก็ควรมีโอกาสเท่ากัน
    อันที่จริง สำหรับจำนวนนับ `k` *ใดๆ* ตัวเลข `1, 2, ..., k`
    เป็นสัดส่วนที่เล็กจนเกือบเป็นศูนย์เมื่อเทียบกับจำนวนนับทั้งหมด ซึ่งหมายความว่า
    โอกาสที่จะสุ่มได้ตัวเลขแบบไม่เอนเอียงจากช่วงนี้แทบจะเท่ากับ `1/∞ = 0`
    พูดอีกแบบคือ สำหรับจำนวนนับ *ใดๆ* เราคาดว่าค่าสุ่มที่ไม่เอนเอียง
    จะต้องมากกว่านั้น ซึ่งเป็นไปไม่ได้ ดังนั้นจึงไม่มีสิ่งใดที่เรียกว่า
    จำนวนนับแบบสุ่มที่ไม่เอนเอียงได้เลย
-   อีกตัวอย่างหนึ่ง: จำนวนจริงระหว่าง 0 กับ 1 จำนวนจริงรวมเศษส่วนทั้งหมด
    จำนวนอตรรกยะอย่าง π และ √2 และพหุคูณของจำนวนเหล่านั้น...
    มีความเป็นไปได้มากมายนับไม่ถ้วน แม้แต่ในช่วงเล็กๆ อย่าง `(0, 1)`
    ดังนั้นการพูดเพียงว่า "ทุกความเป็นไปได้มีโอกาสเท่ากัน" จึงไม่เพียงพอ
    เราตีความ *การไม่มีรูปแบบ* ในอีกแง่หนึ่งแทน นั่นคือ ทุกช่วงที่มีขนาดเท่ากัน
    มีโอกาสเท่ากัน ตัวอย่างเช่น เราอาจแบ่งช่วง `0,1` เป็น `0,½` และ `½,1`
    แล้วโยนเหรียญเพื่อตัดสินว่าค่าสุ่มของเรามาจากช่วงใด สมมติเราเลือก `½,1`
    เราก็โยนเหรียญอีกครั้งเพื่อเลือกระหว่าง `½,¾` กับ `¾,1` ซึ่งจำกัดค่าสุ่ม
    ของเราให้อยู่ในช่วงขนาด `¼` เราทำซ้ำแบบนี้ได้กี่ครั้งก็ได้ตามต้องการ
    เพื่อเลือกค่าสุ่มระหว่าง `0` กับ `1` ด้วยความแม่นยำเท่าที่เราต้องการ
    แม้ว่าเราควรตระหนักว่าเราไม่ได้กำลังเลือกค่า *ที่แน่นอน* แต่เป็นเพียง
    ช่วงเล็กๆ เท่านั้น

สิ่งที่เรานิยาม (หรือนิยามไม่สำเร็จ) ข้างต้นคือการแจกแจงเลขสุ่มแบบสม่ำเสมอ หรือพูดสั้นๆ ว่า **การแจกแจงแบบสม่ำเสมอ** ยังมีการแจกแจงแบบไม่สม่ำเสมอด้วย ดังที่เราจะได้เห็นต่อไป และยังน่าสังเกตตรงนี้ว่าการแจกแจงแบบสม่ำเสมอไม่ได้หมายความว่าค่าที่สุ่มได้จะกระจายตัว *สม่ำเสมอ* (ลองทอยลูกเต๋าหกครั้งสิ คุณคงไม่ได้ 1, 2, 3, 4, 5, 6)

เพื่อกลับมาสู่เรื่องคอมพิวเตอร์ ตอนนี้เราสามารถนิยามได้ว่าค่าสุ่มที่แจกแจงแบบสม่ำเสมอ (ค่าสุ่มที่ไม่เอนเอียง) คืออะไรในหลายบริบท:

-   `u32`: เลขสุ่มระหว่าง 0 กับ `u32::MAX` ที่แต่ละค่า
    มีโอกาสเท่ากัน
-   `BigInt`: เนื่องจากชนิดข้อมูลนี้ไม่มีขอบเขตบน เราจึงไม่สามารถสร้างค่าสุ่ม
    ที่ไม่เอนเอียงได้ (มันจะมีขนาดอนันต์และใช้หน่วยความจำไม่จำกัด)
-   `f64`: เราถือว่ามันเป็นการประมาณจำนวนจริง และ *ตามธรรมเนียมปฏิบัติ*
    จำกัดให้อยู่ในช่วง 0 ถึง 1 (หากไม่ได้ระบุเป็นอย่างอื่น)
    เราจะกลับมาดูการแปลงที่ใช้กันต่อไป;
    ตอนนี้ขอให้ทราบว่าสิ่งเหล่านี้ให้ความแม่นยำ 52-53 บิต (ขึ้นอยู่กับว่าการแปลงแบบใดถูกใช้
    เอาต์พุตจะอยู่ในขั้นของ `ε` หรือ `ε/2` โดย `1+ε` คือค่าที่น้อยที่สุดที่แทนได้ที่มากกว่า `1`)

## ข้อมูลสุ่ม

ดังที่เห็นข้างต้น คำว่า "เลขสุ่ม" ไม่มีความหมายหากไม่มีบริบท "ข้อมูลสุ่ม" โดยทั่วไปหมายถึงลำดับของ *ไบต์* สุ่ม โดยแต่ละไบต์มีค่าที่เป็นไปได้ทั้งหมด 256 ค่าและมีโอกาสเท่ากัน

[`RngCore::fill_bytes`] ให้ผลลัพธ์แบบนี้พอดี นั่นคือลำดับของไบต์สุ่ม

หากลำดับของไบต์สุ่มที่ไม่เอนเอียงและมีความยาวที่ถูกต้องถูกตีความเป็นจำนวนเต็มแทน — เช่น `u32` หรือ `u64` — ผลลัพธ์ก็จะเป็นจำนวนเต็มที่ไม่เอนเอียง เนื่องจากการแปลงนี้ตรงไปตรงมา [`RngCore::next_u32`] และ [`RngCore::next_u64`] จึงอยู่ในเทรตเดียวกัน (อันที่จริงการแปลงมักเป็นอีกทางหนึ่ง นั่นคือตัวสร้างเชิงอัลกอริทึมมักทำงานกับจำนวนเต็มภายใน แล้วค่อยแปลงเป็นรูปแบบข้อมูลสุ่มที่ต้องการ)

[`RngCore::next_u32`]: https://docs.rs/rand_core/latest/rand_core/trait.RngCore.html#tymethod.next_u32
[`RngCore::next_u64`]: https://docs.rs/rand_core/latest/rand_core/trait.RngCore.html#tymethod.next_u64
