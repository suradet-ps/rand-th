# การทดสอบ

ไลบรารี Rand มีชุดยูนิตเทสต์อยู่พอสมควร แม้ว่าจะยังไม่ครอบคลุมครบถ้วนทุกจุดหรือสมบูรณ์แบบที่สุด (เรายินดีต้อนรับการส่งชุดทดสอบเข้ามาปรับปรุงเพิ่มเติมเสมอ) ทั้งนี้ เราต้องการให้มีการเขียนชุดทดสอบกำกับสำหรับฟังก์ชันการทำงานใหม่ๆ ทุกรายการ

ขั้นตอนแรกสุดในการทดสอบคือการรันคำสั่ง `cargo test` จากไดเรกทอรีที่เกี่ยวข้อง และเนื่องจาก Rand รองรับสภาพแวดล้อมหลากหลายรูปแบบ ทั้ง `no_std` (เฉพาะ core), `core+alloc` และสภาพแวดล้อมแบบ `std` เต็มรูปแบบ จึงจำเป็นอย่างยิ่งที่จะต้องทดสอบทั้ง 3 รูปแบบนี้ (ขึ้นอยู่กับว่าโค้ดส่วนที่คุณแก้ไขเกี่ยวข้องกับฟีเจอร์ใดบ้าง):

```sh
# Test using std:
cargo test
# Test using only core:
cargo test --tests --no-default-features
# Test using core + alloc (requires nightly):
cargo +nightly test --tests --no-default-features --features=alloc
```

นอกจากนี้ ยังควรทดสอบร่วมกับฟีเจอร์แฟล็กอื่นๆ ทั้งหมดด้วย:

```sh
cargo test --all-features
```

โปรดทราบว่าคำสั่งเหล่านี้จะทดสอบเฉพาะแพ็กเกจปัจจุบันเท่านั้น (เช่น ไลบรารีหลักของ Rand เมื่อรันจากระดับบนสุดของคลังเก็บโค้ด) หากต้องการทดสอบไลบรารีหรือเครตอื่น ให้ใช้คำสั่ง `cd` ไปยังไดเรกทอรีของเครตนั้นๆ โดยตรง

เราไม่แนะนำให้ใช้แฟล็ก `--package` ของ Cargo เนื่องจากอาจก่อให้เกิด
[ปฏิสัมพันธ์ที่น่าประหลาดใจ](https://github.com/rust-lang/cargo/issues/5364)
กับตัวเลือก `--feature` และล้มเหลวเมื่อมีแพ็กเกจเวอร์ชันเดียวกันหลายตัวอยู่ใน build tree ในระบบ CI ของเราจะใช้แฟล็ก `--manifest-path` ในการเลือกแพ็กเกจแทน แต่ในระหว่างการพัฒนา การใช้คำสั่ง `cd` จะสะดวกและง่ายกว่า

## การเขียนเทสต์

ชุดทดสอบสามารถเขียนได้หลากหลายรูปแบบ ไม่ว่าจะเป็นยูนิตเทสต์ภายในซับโมดูล `test`, ตัวอย่างโค้ดในเอกสาร, แอปพลิเคชันตัวอย่าง (ในไดเรกทอรี `examples`), การทดสอบแบบผสานรวม (ในไดเรกทอรี `tests`) หรือ benchmark (ในไดเรกทอรี `benches`)

โปรดทราบว่ามี*เฉพาะ*ยูนิตเทสต์และการทดสอบแบบผสานรวมเท่านั้นที่คาดว่าจะผ่านในรูปแบบ `no_std` (core เท่านั้น) และ `core+alloc` นี่เป็นทางเลือกโดยเจตนา; โค้ดตัวอย่างควรกำหนดเป้าหมายเฉพาะกรณีทั่วไป (`std`) เท่านั้น

### ตัวสร้างเลขสุ่ม

บ่อยครั้งที่โค้ดทดสอบจำเป็นต้องเรียกใช้ RNG สำหรับประมวลผล แต่ไม่ได้เจาะจงว่าต้องเป็น RNG ตัวใดตัวหนึ่งเป็นพิเศษ ในกรณีนี้ เราแนะนำให้ใช้ `::test::rng` ซึ่งเรียบง่าย เริ่มต้นได้เร็ว และเป็นดีเทอร์มินิสติก:

```rust,ignore
let mut rng = ::test::rng(528); // just pick some number
```

เทสต์หลายตัวเกี่ยวข้องกับคุณสมบัติที่*น่าจะ*เป็นจริง แต่ไม่แน่นอน เราชอบให้เทสต์เช่นนั้นเป็นดีเทอร์มินิสติกเพื่อหลีกเลี่ยงความล้มเหลวที่ไม่จริง
