# ชนิดของตัวสร้าง

ส่วนก่อนหน้าได้แนะนำ [`RngCore`] ซึ่งเป็นเทรตที่*แหล่งข้อมูลสุ่ม* ทุกตัวต้อง implement แต่แท้จริงแล้วแหล่งข้อมูลสุ่มคืออะไร?

ส่วนนี้ว่าด้วยทฤษฎี ดูเพิ่มเติมได้ที่บทว่าด้วย
[ตัวสร้างเลขสุ่ม](guide-rngs.md)

```rust
use rand::{RngExt, SeedableRng};

# fn main() {
// prepare a non-deterministic random number generator:
let mut rng = rand::rng();
println!("{}", rng.random::<i32>()); // prints an unknown value

// prepare a deterministic generator:
let mut rng = rand::rngs::ChaCha8Rng::seed_from_u64(123);
println!("{}", rng.random::<i32>()); // prints -416273517
# }
```

## ตัวสร้างเลขสุ่มแท้

ตัวสร้างเลขสุ่มแบบ**แท้** (TRNG) คือสิ่งที่สร้างเลขสุ่มโดยการสังเกตกระบวนการทางธรรมชาติ เช่น การสลายของอะตอมหรือสัญญาณรบกวนความร้อน (ไม่ว่าสิ่งเหล่านี้จะสุ่ม*อย่างแท้จริง* หรือจริงๆ แล้วเป็นดีเทอร์มินิสติก — ตัวอย่างเช่น หากเอกภพเองเป็นการจำลอง — ก็ไม่ใช่ประเด็นในที่นี้ สำหรับจุดประสงค์ของเรา ก็เพียงพอแล้วที่สิ่งเหล่านี้แยกไม่ออกจากความสุ่มแท้จริง)

โปรดทราบว่ากระบวนการเหล่านี้มักมีความเอนเอียง จึงต้องใช้วิธี*ลดความเอนเอียง* บางรูปแบบเพื่อให้ได้ข้อมูลสุ่มที่ไม่เอนเอียงตามที่ต้องการ

## ตัวสร้างเลขสุ่มเทียม

แน่นอนว่า CPU ถูกออกแบบให้คำนวณแบบดีเทอร์มินิสติก แต่กลับกลายเป็นว่ามันเลียนแบบกระบวนการสุ่มได้ค่อนข้างดี ตัวสร้างเลขสุ่มเทียมส่วนใหญ่เป็นดีเทอร์มินิสติกและนิยามได้ด้วยเพียง:

-   *สถานะ* เริ่มต้นบางอย่าง
-   ฟังก์ชันสำหรับคำนวณค่าสุ่มจากสถานะ
-   ฟังก์ชันสำหรับเลื่อนไปยังสถานะถัดไป
-   (ทางเลือก) ฟังก์ชันสำหรับสร้างสถานะเริ่มต้นจาก *ซีด* หรือ *คีย์*

การที่สิ่งเหล่านี้เป็นดีเทอร์มินิสติกนั้นบางครั้งมีประโยชน์มาก ช่วยให้การจำลอง งานศิลปะแบบสุ่ม หรือเกมสามารถเล่นซ้ำได้อย่างแม่นยำ โดยได้ผลลัพธ์ที่เป็นฟังก์ชันของซีด สำหรับรายละเอียดเพิ่มเติมดูบท
[ความสามารถในการทำซ้ำ](crate-reprod.md) (โปรดทราบว่าความเป็นดีเทอร์มินิสติกเพียงอย่างเดียวไม่เพียงพอที่จะรับประกันความสามารถในการทำซ้ำ)

เสน่ห์อีกอย่างที่โดดเด่นของ PRNG คือความเร็ว: อัลกอริทึมบางตัวใช้เพียงการดำเนินการของ CPU ไม่กี่ครั้งต่อค่าสุ่มหนึ่งค่า จึงสร้างข้อมูลสุ่มได้ตามต้องการเร็วกว่า TRNG ส่วนใหญ่หลายเท่า

อย่างไรก็ตาม โปรดทราบว่า PRNG มีข้อจำกัดหลายประการ:

-   มันแข็งแกร่งได้ไม่เกินซีดของมัน: หากทราบซีดหรือเดาซีดได้
    และทราบอัลกอริทึม (หรือเดาได้) ลำดับเอาต์พุตที่เป็นไปได้ก็จะมีเพียงไม่กี่แบบ
-   เนื่องจากขนาดสถานะมักคงที่ จำนวนค่าเอาต์พุตที่เป็นไปได้จึงมีจำกัด
    ก่อนที่ตัวสร้างจะวนกลับมาซ้ำตัวเอง
-   อัลกอริทึมหลายตัวทำนายได้ง่ายหลังจากเห็นค่าเพียงไม่กี่ค่า และอีกหลายอัลกอริทึม
    ก็ยังไม่ชัดเจนว่าอาจถูก "เจาะ" ได้หรือไม่

## ตัวสร้างเลขสุ่มเทียมเชิงรหัสลับ

ตัวสร้างเลขสุ่มเทียมเชิงรหัสลับ (CSPRNG) คือกลุ่มย่อยของ PRNG ที่ถือว่าปลอดภัย กล่าวคือ:

-   สถานะของมันมีขนาดใหญ่พอที่การลองเดาแบบ brute-force ด้วยการลองค่าเริ่มต้นทั้งหมด
    จะไม่ใช่วิธีที่ทำได้จริงในการค้นหาสถานะเริ่มต้นที่ใช้สร้างลำดับเอาต์พุตที่สังเกตได้
-   และไม่มีอัลกอริทึมอื่นใดที่ดีกว่าวิธี brute-force อย่างเพียงพอ
    จนทำให้สามารถทำนายค่าเอาต์พุตถัดไปได้จริง

การสร้างค่าอย่างปลอดภัยไม่เพียงต้องใช้อัลกอริทึมที่ปลอดภัย (CSPRNG) เท่านั้น แต่ยังต้องมีค่าซีดที่ปลอดภัยและมีขนาดใหญ่พอ (โดยทั่วไป 256 บิต) รวมถึงการป้องกันการโจมตีทางช่องทางข้างเคียง (กล่าวคือ ป้องกันผู้โจมตีอ่านสถานะภายใน)

CSPRNG บางตัวยังมีคุณสมบัติที่สามเพิ่มเติม:

-   CSPRNG มีความต้านทานการย้อนรอย (backtracking resistant) หากผู้โจมตีไม่สามารถ
    คำนวณค่าเอาต์พุตก่อนหน้าของ PRNG ได้ แม้จะค้นพบค่าของสถานะภายในปัจจุบันแล้ว
    (ซึ่งหมายความว่าเอาต์พุตในอนาคตทั้งหมดถูกเปิดเผย)

## ตัวสร้างเลขสุ่มแบบฮาร์ดแวร์

ตัวสร้างเลขสุ่มแบบ**ฮาร์ดแวร์** (HRNG) ในทางทฤษฎีคือตัวแปลงจาก TRNG บางชนิดเป็นข้อมูลดิจิทัล ในทางปฏิบัติ สิ่งเหล่านี้อาจใช้ PRNG เพื่อลดความเอนเอียงของ TRNG แม้ว่า HRNG จะมี TRNG อยู่เบื้องหลัง แต่ก็ไม่รับประกันว่าจะปลอดภัย: ตัว TRNG เองอาจให้เอนโทรปีไม่เพียงพอ (คือทำนายได้ง่ายเกินไป) หรือกระบวนการขยายสัญญาณและลดความเอนเอียงอาจมีข้อบกพร่อง

HRNG อาจถูกใช้เพื่อให้ซีดสำหรับ PRNG แม้ว่าโดยปกติแล้วนี่จะไม่ใช่วิธีเดียวในการได้ซีดที่ปลอดภัย (ดูส่วนถัดไป) HRNG อาจใช้แทน PRNG ทั้งตัวก็ได้ แต่เนื่องจากตอนนี้เรามี PRNG ซอฟต์แวร์ที่เร็วมากและแข็งแกร่งมาก และเนื่องจากการ implement ด้วยซอฟต์แวร์ตรวจสอบได้ง่ายกว่าฮาร์ดแวร์ วิธีนี้จึงมักไม่ใช่ทางเลือกที่นิยม

เนื่องจาก PRNG ต้องมีค่าซีดสุ่มจึงจะปลอดภัย HRNG อาจถูกใช้เพื่อให้ซีดนั้น หรือแม้กระทั่งแทนความจำเป็นของ PRNG อย่างไรก็ตาม เนื่องจากเป้าหมายมักเป็นเพียง "แค่" การสร้างค่าสุ่มที่ทำนายไม่ได้ จึงมีทางเลือกที่ยอมรับได้แทนตัวสร้างเลขสุ่ม*แท้* (ดูส่วนถัดไป)

## เอนโทรปี

ตามที่กล่าวข้างต้น CSPRNG จะปลอดภัยได้ ค่าซีดของมันก็ต้องปลอดภัยด้วย คำว่า *เอนโทรปี* ใช้ได้สองความหมาย:

-   ในความหมายของการวัดปริมาณข้อมูลที่ไม่ทราบค่าในข้อมูลบางส่วน
-   ในความหมายของข้อมูลที่ไม่ทราบค่าจำนวนหนึ่ง

ในอุดมคติแล้ว ค่าบูลีนสุ่มหรือการโยนเหรียญหนึ่งครั้งมีเอนโทรปี 1 บิต แม้ว่าหากค่าเอนเอียง ก็จะมีน้อยกว่านั้น เอนโทรปีของแชนนอน (Shannon Entropy) พยายามวัดปริมาณนี้

ตัวอย่างเช่น Unix time-stamp (จำนวนวินาทีนับจากต้นปี 1970) มีทั้งข้อมูลความละเอียดสูงและต่ำ โดยทั่วไปนี่คือตัวเลข 32 บิต แต่ปริมาณ*เอนโทรปี*จะขึ้นอยู่กับว่าผู้โจมตีในสมมติฐานสามารถเดาตัวเลขได้แม่นยำเพียงใด หากผู้โจมตีเดาตัวเลขได้ใกล้เคียงถึงระดับนาที ค่านี้อาจมีประมาณ 6 บิต (2^6 = 64) หากผู้โจมตีเดาได้ถึงระดับวินาที ค่านี้ก็เป็น 0 บิต [`JitterRng`] ใช้แนวคิดนี้ในการเก็บเกี่ยวเอนโทรปีโดยไม่ต้องมี HRNG (แต่ใช้ตัวจับเวลาความละเอียดระดับนาโนวินาทีและตั้งสมมติฐานแบบอนุรักษ์นิยมว่ามีเอนโทรปีเพียงไม่กี่บิตต่อ time-stamp หนึ่งค่า หลังจากทดสอบคุณภาพของตัวจับเวลาหลายรอบแล้ว)

[`JitterRng`]: https://docs.rs/rand_jitter/latest/rand_jitter/struct.JitterRng.html
