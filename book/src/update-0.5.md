# การอัปเดตเป็น 0.5

รีลีส 0.5 มีการเปลี่ยนแปลงที่สำคัญพอสมควรเมื่อเทียบกับรีลีส 0.4 ดังนั้นจึงควรอ่านรายละเอียดการเปลี่ยนแปลงที่ทำให้โค้ดเดิมใช้ไม่ได้ต่อไปนี้ให้ครบถ้วน รีลีสนี้ยังมีการปรับแต่งประสิทธิภาพอีกมากซึ่งไม่ได้กล่าวถึงในรายละเอียดด้านล่าง

## เครต

เรามีเครตใหม่: `rand_core`! เครตนี้บรรจุเทรตสำคัญบางตัว ได้แก่ `RngCore`, `BlockRngCore`, `SeedableRng` และ `CryptoRng` ชนิดข้อมูลข้อผิดพลาด รวมถึงโมดูลสองโมดูลที่มีตัวช่วยสำหรับการ implement คือ `le` และ `impls` แนะนำให้ผู้ที่ implement ตัวสร้างใช้เครต `rand_core` ขณะที่ผู้ใช้อื่นใช้เฉพาะเครต `rand` ซึ่ง re-export ส่วนใหญ่ของ `rand_core`

เครต `rand_derive` ถูกเลิกใช้ (deprecated) เนื่องจากมีการใช้งานต่ำมากและการเลิกใช้ `Rand`

## ฟีเจอร์

มีฟีเจอร์แฟล็กของ Cargo เพิ่มใหม่หลายตัว:

-   `alloc` ใช้โดยไม่มี `std` เพื่อให้ใช้ `Box` และ `Vec` ได้
-   `serde1` เพิ่มการรองรับการซีเรียลไลซ์ให้กับ PRNG บางตัว
-   `log` เพิ่มการล็อกในบางจุด (หลักๆ ที่ `OsRng` และ `JitterRng`)

## `Rng` และเพื่อนๆ (เทรตหลัก)

เทรต `Rng` ถูกแยกออกเป็นสองเทรต คือ `RngCore` ฝั่ง "แบ็กเอนด์" (implement โดยตัวสร้าง) และ `Rng` ฝั่ง "ฟรอนต์เอนด์" ที่ implement เมธอดส่วนขยายที่สะดวกทั้งหมด

ผู้ที่ implement ตัวสร้างต้อง `impl RngCore` แทน แนะนำให้ใช้ `rand_core` สำหรับการ implement; โมดูล `rand_core::{le, impls}` อาจมีประโยชน์

ผู้ใช้ `Rng` *ที่ไม่จำเป็นต้อง implement มัน* ไม่ต้องแก้ไขมากนัก บ่อยครั้งผู้ใช้ลืมเรื่อง `RngCore` ได้และ import เฉพาะ `Rng` แทนที่จะใช้ `RngCore::next_u32()` / `next_u64()` ผู้ใช้ควรใช้ `Rng::gen()` และแทนที่จะใช้ `RngCore::fill_bytes(dest)` ก็ใช้ `Rng::fill(dest)` ได้

### เมธอดของ `Rng` / `RngCore`

เพื่อรองรับการจัดการข้อผิดพลาดจากแหล่งที่ล้มเหลวได้ (เช่น `OsRng`) จึงเพิ่มเมธอด `RngCore::try_fill_bytes` ใหม่; ตัวอย่างเช่น `EntropyRng` ใช้กลไกนี้เพื่อถอยไปใช้ `JitterRng` หาก `OsRng` ล้มเหลว และตัวจัดการต่างๆ ก็สร้างข้อความข้อผิดพลาดที่ดีขึ้น
เช่นเดิม เมธอดอื่นๆ จะ panic เมื่อล้มเหลว แต่เนื่องจากเมธอดเหล่านี้มักใช้กับตัวสร้างเชิงอัลกอริทึมซึ่งปกติไม่ล้มเหลว จึงถือเป็นการประนีประนอมที่เหมาะสม

เมธอดบางตัวจาก `Rng` เดิมถูกนำออกหรือเลิกใช้:

-   `next_f32` และ `next_f64`; ตัวสร้างไม่สามารถ implement สิ่งเหล่านี้ได้อีกต่อไป ให้ใช้ `gen` แทน
-   `gen_iter`; ผู้ใช้อาจใช้อิเทอเรเตอร์มาตรฐานกับโคลเชอร์แทน:
    `::std::iter::repeat(()).map(|()| rng.gen())`
-   `gen_ascii_chars`; ใช้ `repeat` ตามข้างต้นและ `rng.sample(Alphanumeric)`
-   `gen_weighted_bool(n)`; ใช้ `gen_bool(1.0 / n)` แทน

`Rng` มีเมธอดใหม่บางตัว:

-   `sample(distr)` เป็นทางลัดสำหรับ `distr.sample(rng)` สำหรับ `Distribution` ใดๆ
-   `gen_bool(p)` สร้างค่าบูลีนโดยมีความน่าจะเป็น `p` ที่จะเป็นจริง
-   `fill` และ `try_fill` ซึ่งสอดคล้องกับ `fill_bytes` และ `try_fill_bytes` ตามลำดับ (กล่าวคือ ต่างกันแค่การจัดการข้อผิดพลาด); สิ่งเหล่านี้เติมสไลซ์จำนวนเต็ม / แอเรย์ได้โดยตรง และให้ประสิทธิภาพดีกว่า `gen()`

### การสร้าง PRNG

#### PRNG ที่เริ่มต้นแบบสุ่มใหม่

มีเทรตใหม่ถูกเพิ่มเข้ามา: `FromEntropy` เทรตนี้ถูก implement โดยอัตโนมัติสำหรับชนิดข้อมูลใดๆ ที่รองรับ `SeedableRng` และให้การสร้างจากเอนโทรปีใหม่ที่แข็งแกร่ง:

```rust,noplayground
# extern crate rand_0_5 as rand;
use rand::{ChaChaRng, FromEntropy};

let mut rng = ChaChaRng::from_entropy();
```

#### การซีด PRNG

เทรต `SeedableRng` ถูกแก้ไขให้รวมชนิดซีดผ่าน associated type (`SeedableRng::Seed`) แทนพารามิเตอร์เทมเพลต (`SeedableRng<Seed>`) นอกจากนี้ PRNG ทุกตัวตอนนี้ซีดจากอาร์เรย์ไบต์ (`[u8; N]` สำหรับ N คงที่) ซึ่งทำให้จัดการการซีด PRNG แบบเจเนอริกได้ ซึ่งก่อนหน้านี้ทำไม่ได้

PRNG ไม่ได้ถูกสร้างจาก PRNG อื่นผ่านการรองรับ `Rand` / `gen()` อีกต่อไป แต่ผ่าน `SeedableRng::from_rng` ซึ่งรองรับการจัดการข้อผิดพลาดและตั้งใจให้ชัดเจน

`SeedableRng::reseed` ถูกนำออก เนื่องจากไม่มีประโยชน์เหนือ `from_seed` และข้อได้เปรียบด้านประสิทธิภาพของมันก็ไม่ชัดเจน

ผู้ที่ implement `SeedableRng` อาจต้องเปลี่ยนชนิด `Seed` ของตนเป็นอาร์เรย์ไบต์; ข้อจำกัดนี้ตั้งขึ้นเพื่อรับประกันการจัดการ Endianness ที่พอร์ตได้ มีฟังก์ชันตัวช่วยใน `rand_core::le` สำหรับอ่านค่า `u32` และ `u64` จากอาร์เรย์ไบต์

### PRNG แบบบล็อก

rand_core มีเทรตตัวช่วยใหม่ชื่อ `BlockRngCore` และ implement ชื่อ `BlockRng` สิ่งเหล่านี้มีไว้สำหรับตัวสร้างที่สร้างข้อมูลสุ่มทีละบล็อกแทนที่จะเป็นค่าขนาดหนึ่งคำ การใช้เทรตและ implement นี้มีข้อดีสองประการ: มีเมธอด `RngCore` ที่ปรับแต่งประสิทธิภาพแล้วให้ใช้ และ PRNG สามารถใช้กับ `ReseedingRng` ได้โดยมีภาระต่ำมาก

### RNG เชิงรหัสลับ

มีเทรตใหม่ถูกเพิ่มเข้ามา: `CryptoRng` นี่เป็นเพียงมาร์กเกอร์เทรตที่บ่งชี้ว่าตัวสร้างตัวใดควรเหมาะสมกับการเข้ารหัส เช่น
`fn foo<R: Rng + CryptoRng>(rng: &mut R)` *ไม่สามารถรับประกันความเหมาะสมต่อการใช้งานเชิงรหัสลับได้*

## การจัดการข้อผิดพลาด

มีชนิดข้อมูล `Error` ใหม่ถูกเพิ่มเข้ามา ซึ่งออกแบบมาเพื่อความเข้ากันได้กับ no-std โดยเฉพาะ ความเรียบง่าย และความยืดหยุ่นเพียงพอต่อการใช้งานของเรา (บรรจุ `cause` เมื่อเป็นไปได้):
```rust,noplayground
# extern crate rand_0_5 as rand;
# use rand::ErrorKind;
pub struct Error {
    pub kind: ErrorKind,
    pub msg: &'static str,
    // some fields omitted
}
```
`ErrorKind` ที่เกี่ยวข้องช่วยให้จำแนกข้อผิดพลาดแบบกว้างๆ ได้เป็นแบบถาวร ไม่คาดคิด ชั่วคราว และยังไม่พร้อม

สิ่งต่อไปนี้ใช้ชนิดข้อผิดพลาดใหม่:

-   `RngCore::try_fill_bytes`
-   `Rng::try_fill`
-   `OsRng::new`
-   `JitterRng::new`

## ตัวสร้างภายนอก

เรามีตัวสร้างใหม่ชื่อ `EntropyRng` ซึ่งห่อหุ้ม `OsRng` และ `JitterRng` (เลือกใช้ตัวแรกเป็นหลัก แต่ถอยไปใช้ตัวหลังเมื่อจำเป็น) สิ่งนี้ทำให้สร้างได้ง่ายพร้อมการถอยกลับผ่าน `SeedableRng::from_rng`
เช่น `IsaacRng::from_rng(EntropyRng::new())?` ซึ่งเทียบเท่ากับการใช้ `FromEntropy` ยกเว้นเรื่องการจัดการข้อผิดพลาด

แนะนำให้ใช้ `EntropyRng` แทน `OsRng` เพื่อหลีกเลี่ยงข้อผิดพลาดบนแพลตฟอร์มที่ตัวสร้างของระบบเสีย แต่ควรทราบว่าการถอยไปใช้ `JitterRng` นั้นช้ามาก

## PRNG

*ตัวสร้างเลขสุ่มเทียม* (กล่าวคือ ตัวสร้างเชิงอัลกอริทึมแบบดีเทอร์มินิสติก) มีการเปลี่ยนแปลงบางอย่างตั้งแต่ 0.4 และตอนนี้อยู่ในโมดูล `prng` (ชื่อเดิมยังใช้ได้ชั่วคราวเพื่อความเข้ากันได้; ในที่สุดตัวสร้างเหล่านี้คงจะย้ายไปอยู่นอกเครต `rand`)

PRNG ทุกตัวตอนนี้ไม่ implement `Copy` เพื่อป้องกันการคัดลอกสถานะของตัวสร้างโดยไม่ตั้งใจ (และป้องกันการเกิดค่าซ้ำ) การโคลนอย่างชัดเจนผ่าน `Clone` ยังใช้ได้ PRNG ทุกตัวตอนนี้มีการ implement `Debug` แบบกำหนดเองซึ่งไม่พิมพ์สถานะภายในใดๆ; สิ่งนี้ช่วยหลีกเลี่ยงการรั่วไหลของสถานะตัวสร้างเชิงรหัสลับลงในไฟล์ล็อกโดยไม่ตั้งใจ แนะนำให้ผู้ที่ implement PRNG ภายนอกทำตามแนวทางนี้ (ดูเอกสารของ `RngCore` ด้วย)

`SmallRng` ถูกเพิ่มเข้ามาเป็นตัวห่อหุ้ม ปัจจุบันห่อหุ้ม `XorShiftRng` (แต่คงจะเปลี่ยนเป็นอัลกอริทึมอื่นในไม่ช้า) สำหรับการใช้งานที่สถานะเล็กและเริ่มต้นเร็วเป็นสิ่งสำคัญ แต่ไม่ต้องการความแข็งแกร่งเชิงรหัสลับ (ประสิทธิภาพจริงของการสร้างค่าแตกต่างกันตาม benchmark; ขึ้นอยู่กับการใช้งาน มันอาจเป็นหรือไม่เป็นอัลกอริทึมที่เร็วที่สุด แต่จะเร็วเสมอ)

### `ReseedingRng`

ตัวห่อหุ้ม `ReseedingRng` ถูกแก้ไขอย่างมีนัยสำคัญเพื่อลดภาระ น่าเสียดายที่ `ReseedingRng` ใหม่ไม่เข้ากันได้กับ RNG ทุกตัว แต่ใช้ได้เฉพาะตัวที่ใช้ `BlockRngCore`

### ChaCha

เมธอด `ChaChaRng::set_counter` ถูกแทนที่ด้วยเมธอดใหม่สองตัว คือ `set_word_pos` และ `set_stream` เมื่อจำเป็น พฤติกรรมของเมธอดเดิมอาจเลียนแบบได้ดังนี้:

```rust,noplayground
# extern crate rand_0_5 as rand;
# use rand::prelude::*;
# use rand_chacha_0_1::ChaChaRng;
# fn main() {
let lower = 88293;
let higher = 9300932;

// previously:
// let mut rng = rand::ChaChaRng::new_unseeded();
// rng.set_counter(lower, higher);

// now:
let mut rng = ChaChaRng::from_seed([0u8; 32]);
rng.set_word_pos(lower << 4);
rng.set_stream(higher);

assert_eq!(4060232610, rng.next_u32());
assert_eq!(2786236710, rng.next_u32());
# }
```

### PRNG ตระกูล ISAAC

PRNG `IsaacRng` และ `Isaac64Rng` ตอนนี้มีเมธอดสร้างเพิ่มเติม: `new_from_u64(seed)` สถานะ 64 บิตไม่เพียงพอสำหรับการเข้ารหัส แต่อาจมีประโยชน์ในการจำลองและเกม ในอนาคตสิ่งนี้อาจถูกแทนที่ด้วยเมธอดสำหรับสร้าง PRNG ใดๆ จากออบเจกต์ที่แฮชได้

### HC-128

นี่คือตัวสร้างเชิงรหัสลับใหม่ ซึ่งถูกเลือกโดย eSTREAM ให้เป็นหนึ่งใน "ไซเฟอร์แบบสตรีมที่เหมาะแก่การนำไปใช้อย่างกว้างขวาง" ตอนนี้มันเป็นตัวสร้างเชิงรหัสลับค่าเริ่มต้น ใช้โดย `StdRng` และ `thread_rng()`

## ฟังก์ชัน/เทรตตัวช่วย

เทรต `Rand` ถูกเลิกใช้ (deprecated) แทนที่นั้น ผู้ใช้ควรใช้ `Standard` ซึ่งเป็นการแจกแจงจริงและรองรับการสุ่มแบบเดียวกับ `Rand` `Rng::gen()` ตอนนี้ใช้ `Standard` และควรทำงานเหมือนเดิมทุกประการ ดูเอกสารของโมดูล `distributions` เกี่ยวกับวิธี implement `Distribution<T>` สำหรับ `Standard` ให้กับชนิดข้อมูลที่ผู้ใช้กำหนด `T`

`weak_rng()` ถูกเลิกใช้; ใช้ `SmallRng::from_entropy()` แทน

## การแจกแจง

เทรต `Sample` และ `IndependentSample` ถูกแทนที่ด้วยเทรตเดียว คือ `Distribution` ซึ่งเทียบเท่ากับ `IndependentSample` เป็นส่วนใหญ่ แต่ `ind_sample` ถูกแทนที่ด้วย `sample` เฉยๆ การรองรับการแจกแจงที่แก้ไขได้ถูกยกเลิก; แม้ดูเหมือนอาจมีกรณีใช้งานจริงอยู่บ้าง แต่มันไม่ได้ถูกใช้กว้างขวางพอที่จะอ้างความชอบธรรมให้มีเทรตอิสระสองตัว หรือต้องให้เข้าถึงออบเจกต์การแจกแจงแบบแก้ไขได้ ทั้ง `Sample` และ `IndependentSample` ยังใช้ได้ แต่ถูกเลิกใช้; และจะถูกนำออกในรีลีสในอนาคต

`Distribution::sample` (รวมถึงฟังก์ชันอื่นๆ อีกหลายตัว) ตอนนี้เรียกบน RNG ที่ลบชนิดข้อมูลแล้ว (unsized) ได้โดยตรง

`RandSample` ถูกนำออก (ดูการเลิกใช้ `Rand` และการแจกแจง `Standard` ใหม่)

ตัวห่อหุ้ม `Closed01` ถูกนำออก แต่ `OpenClosed01` ถูกเพิ่มเข้ามา

### การแจกแจงแบบสม่ำเสมอ

มีการแจกแจงใหม่สองแบบ:

-   `Standard` สร้างค่าตัวอย่างแบบสม่ำเสมอสำหรับชนิดข้อมูลต่างๆ มากมาย
    และทำหน้าที่แทน `Rand`
-   `Alphanumeric` สุ่ม `char` จากช่วง `a-z A-Z 0-9`

#### ช่วง

การแจกแจง `Range` ถูกปรับแก้อย่างมาก และเปลี่ยนชื่อเป็น `Uniform`:

-   `Uniform::new(low, high)` ยังคงอยู่ (ครึ่งเปิด `[low, high)`)
-   `Uniform::new_inclusive(low, high)` ถูกเพิ่มเข้ามา โดยรวม `high` ในช่วงการสุ่ม
-   `Uniform::sample_single(low, high, rng)` เป็นแบบที่เร็วกว่าสำหรับการสุ่มครั้งเดียวจาก `[low, high)`

`Uniform` ตอนนี้ implement ให้กับชนิดข้อมูลที่ผู้ใช้กำหนดได้; ดูโมดูล `uniform`

### การแจกแจงแบบไม่สม่ำเสมอ

มีการแจกแจงสองแบบถูกเพิ่มเข้ามา:

-   Poisson จำลองจำนวนเหตุการณ์ที่คาดหวังจากแหล่งที่มีอัตราคงที่ภายในช่วงเวลาคงที่ (เช่น การสลายตัวของนิวเคลียส)
-   Binomial จำลองผลลัพธ์ของการทดลองใช่-ไม่ใช่จำนวนคงที่ครั้ง

เมธอดการสุ่มอิงจากเมธอดใน "Numerical Recipes in C"

#### การแจกแจงแบบเอกซ์โพเนนเชียลและ Normal

การแจกแจงหลัก `Exp` และ `Normal` ไม่เปลี่ยนแปลง อย่างไรก็ตามเวอร์ชัน "มาตรฐาน" คือ `Exp1` และ `StandardNormal` ไม่ได้เป็นชนิดตัวห่อหุ้มอีกต่อไป แต่เป็นการแจกแจงเต็มรูปแบบ แทนที่จะเขียน `let Exp1(x) = rng.gen();` ตอนนี้คุณเขียน
`let x = rng.sample(Exp1);`
