# ขอบเขต

เมื่อเวลาผ่านไป ขอบเขตของโปรเจกต์เติบโตขึ้น และ Rand ได้เปลี่ยนจากการใช้เครตแบบ monolithic มาเป็นเครต "หลัก" บวกกับเครตเฉพาะทางหลายตัว สำหรับฟังก์ชันใหม่ ต้องพิจารณาว่ามันเข้ากับโปรเจกต์ Rand หรือไม่ และเข้ากับส่วนใด

เครตขนาดเล็กที่มุ่งเน้นเฉพาะทางอาจถูกใช้ด้วยเหตุผลบางประการ แต่เรา*ไม่*ได้ตั้งเป้าที่จะแบ่งฟังก์ชันการทำงานออกเป็นเครตเล็กๆ ให้มากที่สุด เหตุผลที่ชอบด้วยเหตุผลสำหรับการใช้เครตแยกสำหรับฟีเจอร์หนึ่งๆ จึงได้แก่:

-   เพื่อให้มีลำดับชั้นของดีเพนเดนซีที่ชัดเจน (`rand_core`)
-   เพื่อทำให้ฟีเจอร์พร้อมใช้งานในลักษณะที่ใช้เดี่ยวๆ ได้ (เช่น `getrandom`)
-   เพื่อย้ายฟีเจอร์ที่ใช้น้อยแต่มียอดโค้ดไม่น้อยออกจากเครตที่ใช้กันแพร่หลาย (เช่น `rand_jitter` และ `rand_distr` ต่างก็ย้ายฟังก์ชันการทำงานออกจาก `rand`)
-   เพื่อให้มีทางเลือก โดยไม่ต้องรวมโค้ดที่ไม่ได้ใช้จำนวนมากไว้ให้ผู้ใช้ทุกคน แต่ก็ไม่ต้องสร้างเครตใหม่จำนวนมหาศาล (เครตตระกูล RNG อย่าง `rand_xoshiro` และ `rand_isaac`)


## เทรต พื้นฐาน และ UI

อินเทอร์เฟซหลักสำหรับผู้ใช้ของโปรเจกต์ Rand ยังคงเป็นเครต `rand` ศูนย์กลาง เป้าหมายของเครตนี้คือ:

-   ใช้งานง่าย
-   เปิดเผยฟังก์ชันที่ใช้บ่อยในที่เดียว
-   อนุญาตให้ใช้แหล่งความสุ่มเพิ่มเติมและตัวสุ่มของการแจกแจงอื่นๆ

เพื่อให้มีความเป็นโมดูลาร์ที่ดีขึ้น เทรตหลักถูกย้ายไปยังเครต `rand_core` เป้าหมายของเครตนี้คือ:

-   เปิดเผยเทรตหลักโดยมีดีเพนเดนซีน้อยที่สุด
-   ให้เครื่องมือทั่วไปที่จำเป็นสำหรับการ implement แหล่งความสุ่มต่างๆ

## แหล่งความสุ่มภายนอก

แหล่งความสุ่มภายนอกหลัก (และมักเป็นเพียงแหล่งเดียว) คือระบบปฏิบัติการ ซึ่งเชื่อมต่อผ่านเครต `getrandom` เครตนี้ยังรองรับการใช้ RDRAND บนเป้าหมาย `no_std` บางตัว

การรองรับเป้าหมาย `no_std` อื่นๆ ได้รับการพูดคุยกันแล้ว แต่มีความพยายามในการ implement จริงน้อยมาก ดู
[getrandom#4](https://github.com/rust-random/getrandom/issues/4)

เครต `rand_jitter` ให้การ implement ตัวเก็บเกี่ยวเอนโทรปีแบบ
[CPU Jitter](http://www.chronox.de/jent.html) และถูกรวมไว้ใน Rand ด้วยเหตุผลทางประวัติศาสตร์เท่านั้น


## ตัวสร้างเลขสุ่มเทียม

ไลบรารี Rand รวมตัวสร้างเลขสุ่มเทียมหลายตัว ด้วยเหตุผลดังนี้:

-   เพื่อ implement ตัวสร้าง `StdRng` และ `SmallRng`
-   เพื่อให้ตัวสร้างทางเลือกคุณภาพสูงบางตัว
-   การใช้งานในอดีต

สิ่งเหล่านี้ถูก implement ภายในเครต "ตระกูล" เช่น `chacha20`, `rand_pcg`,
`rand_xoshiro`

เราได้รับคำขอหลายครั้งให้นำอัลกอริทึมใหม่เข้ามาในไลบรารี เมื่อประเมินคำขอเช่นนั้น เราต้องพิจารณาหลายสิ่ง:

-   จุดประสงค์ของการรวมไว้ใน Rand
-   PRNG นั้นปลอดภัยเชิงรหัสลับหรือไม่ และหากใช่ ข้อกล่าวอ้างเช่นนั้นน่าเชื่อถือเพียงใด
-   คุณภาพทางสถิติของเอาต์พุต
-   ประสิทธิภาพและฟีเจอร์ของตัวสร้าง
-   การตอบรับและการรีวิวโดยบุคคลที่สามต่ออัลกอริทึม

## การแจกแจง

เทรต `Distribution` ถูกจัดเตรียมโดย Rand พร้อมกับการแจกแจงที่ใช้บ่อย (ส่วนใหญ่เป็นแบบเชิงเส้น)

การแจกแจงเพิ่มเติมถูกบรรจุอยู่ในเครต `rand_distr` ซึ่งพึ่งพา `rand` และ re-export การแจกแจงทั้งหมดของมัน
