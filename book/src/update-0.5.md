# การอัปเดตเป็น 0.5

ในเวอร์ชัน 0.5 มีการเปลี่ยนแปลงครั้งสำคัญค่อนข้างมากเมื่อเทียบกับ 0.4 จึงขอแนะนำให้อ่านรายละเอียดเกี่ยวกับการเปลี่ยนแปลงที่อาจส่งผลกระทบต่อโค้ดเดิม (breaking changes) ด้านล่างนี้อย่างถี่ถ้วน นอกจากนี้ เวอร์ชันนี้ยังมีการปรับปรุงประสิทธิภาพขนานใหญ่อีกหลายจุดที่ไม่ได้ระบุไว้ในรายละเอียดด้านล่าง

## เครต

เราได้เพิ่มเครตใหม่คือ `rand_core`! เครตนี้รวบรวมเทรตหลักที่สำคัญ เช่น `RngCore`, `BlockRngCore`, `SeedableRng` และ `CryptoRng`, ประเภทข้อผิดพลาด (error type) ตลอดจนสองโมดูลตัวช่วยสำหรับการอิมพลีเมนต์ ได้แก่ `le` และ `impls` สำหรับผู้ที่ต้องการอิมพลีเมนต์ตัวสร้างเลขสุ่ม ขอแนะนำให้เรียกใช้เครต `rand_core` โดยตรง ส่วนผู้ใช้งานทั่วไปสามารถใช้เพียงเครต `rand` ซึ่งทำการ re-export รายการส่วนใหญ่จาก `rand_core` ให้อยู่แล้ว

เครต `rand_derive` ถูกยกเลิกการใช้งาน (deprecated) เนื่องจากมีอัตราการใช้งานต่ำมากและมีการเลิกใช้เทรต `Rand` ไปแล้ว

## ฟีเจอร์

มีฟีเจอร์แฟล็กของ Cargo เพิ่มใหม่หลายตัว:

-   `alloc` เปิดใช้งานเมื่อไม่ใช้ `std` เพื่อให้สามารถใช้งาน `Box` และ `Vec` ได้
-   `serde1` เพิ่มการรองรับการทำ serialization ให้กับ PRNG บางตัว
-   `log` เพิ่มการบันทึก log ในบางจุด (โดยหลักอยู่ที่ `OsRng` และ `JitterRng`)

## `Rng` และเพื่อนๆ (เทรตหลัก)

เทรต `Rng` ถูกแยกออกเป็น 2 เทรต ได้แก่ `RngCore` ฝั่ง "แบ็กเอนด์" (อิมพลีเมนต์โดยตัวสร้างเลขสุ่ม) และ `Rng` ฝั่ง "ฟรอนต์เอนด์" ซึ่งมี extension method อำนวยความสะดวกอย่างครบครัน

ผู้พัฒนาที่ต้องการอิมพลีเมนต์ตัวสร้างเลขสุ่มจะต้องเปลี่ยนมา `impl RngCore` แทน ขอแนะนำให้ใช้ `rand_core` สำหรับการพัฒนา โดยโมดูล `rand_core::{le, impls}` จะมีตัวช่วยที่เป็นประโยชน์อย่างมาก

สำหรับผู้ใช้ `Rng` *ที่ไม่จำเป็นต้องอิมพลีเมนต์ตัวสร้างเอง* แทบไม่ต้องปรับแก้โค้ดเลย บ่อยครั้งคุณไม่จำเป็นต้องนึกถึง `RngCore` และเพียงแค่อิมพอร์ต `Rng` เข้ามาใช้งานเท่านั้น โดยแทนที่จะเรียก `RngCore::next_u32()` / `next_u64()` ให้เปลี่ยนมาใช้ `Rng::gen()` และแทนที่จะใช้ `RngCore::fill_bytes(dest)` ก็สามารถใช้ `Rng::fill(dest)` แทนได้

### เมธอดของ `Rng` / `RngCore`

เพื่อรองรับการจัดการข้อผิดพลาดจากแหล่งกำเนิดที่อาจเกิดความผิดพลาดได้ (เช่น `OsRng`) จึงได้เพิ่มเมธอด `RngCore::try_fill_bytes` ขึ้นมาใหม่ ตัวอย่างเช่น `EntropyRng` จะใช้กลไกนี้เพื่อสลับไปใช้ `JitterRng` สำรองหาก `OsRng` ล้มเหลว และมีข้อความแจ้งข้อผิดพลาดที่ชัดเจนยิ่งขึ้น
ส่วนเมธอดอื่นๆ จะยังคง panic เมื่อเกิดข้อผิดพลาดเช่นเดิม แต่เนื่องจากเมธอดเหล่านั้นมักถูกใช้กับตัวสร้างเชิงอัลกอริทึมที่โดยปกติไม่มีทางทำงานล้มเหลว จึงถือเป็นแนวทางที่เหมาะสมและลงตัว

เมธอดบางตัวจาก `Rng` เดิมถูกนำออกหรือเลิกใช้:

-   `next_f32` และ `next_f64`: ตัวสร้างเลขสุ่มไม่สามารถอิมพลีเมนต์เมธอดเหล่านี้ได้โดยตรงอีกต่อไป ให้เปลี่ยนมาใช้ `gen` แทน
-   `gen_iter`: ให้เปลี่ยนไปใช้อิเทอเรเตอร์มาตรฐานของ Rust ร่วมกับคลอเชอร์แทน:
    `::std::iter::repeat(()).map(|()| rng.gen())`
-   `gen_ascii_chars`: ให้ใช้ `repeat` ตามแบบด้านบนร่วมกับ `rng.sample(Alphanumeric)`
-   `gen_weighted_bool(n)`: ให้เปลี่ยนมาใช้ `gen_bool(1.0 / n)` แทน

`Rng` มีเมธอดใหม่เพิ่มเติมเข้ามา:

-   `sample(distr)` เป็นทางลัดแทนการเรียก `distr.sample(rng)` สำหรับ `Distribution` ใดๆ
-   `gen_bool(p)` สุ่มค่าบูลีนโดยมีความน่าจะเป็นเท่ากับ `p` ที่จะได้ผลลัพธ์เป็น true
-   `fill` และ `try_fill` สอดคล้องกับ `fill_bytes` และ `try_fill_bytes` ตามลำดับ (ต่างกันตรงการส่งต่อข้อผิดพลาด) เมธอดเหล่านี้สามารถเติมข้อมูลลงในสไลซ์จำนวนเต็มหรืออาร์เรย์ได้โดยตรง และให้ประสิทธิภาพที่ดีกว่า `gen()`

### การสร้าง PRNG

#### PRNG ที่สุ่มค่าตั้งต้นใหม่

มีการเพิ่มเทรตใหม่: `FromEntropy` เทรตนี้ได้รับการอิมพลีเมนต์โดยอัตโนมัติให้กับทุกประเภทข้อมูลที่รองรับ `SeedableRng` ช่วยให้สามารถสร้างตัวสร้างเลขสุ่มจากแหล่งเอนโทรปีที่สดใหม่และมั่นคงปลอดภัยได้โดยสะดวก:

```rust,noplayground
# extern crate rand_0_5 as rand;
use rand::{ChaChaRng, FromEntropy};

let mut rng = ChaChaRng::from_entropy();
```

#### การกำหนดซีดให้กับ PRNG

เทรต `SeedableRng` ได้รับการปรับปรุงให้กำหนดประเภทของซีดผ่าน associated type (`SeedableRng::Seed`) แทนที่จะใช้พารามิเตอร์เทมเพลต (`SeedableRng<Seed>`) ยิ่งไปกว่านั้น PRNG ทุกตัวในตอนนี้จะรับซีดเป็นอาร์เรย์ของไบต์ (`[u8; N]` โดยที่ N มีขนาดคงที่) ทำให้สามารถจัดการการกำหนดซีดให้กับ PRNG แบบเจเนอริกได้อย่างที่เคยทำไม่ได้มาก่อน

PRNG จะไม่สามารถสร้างขึ้นจาก PRNG อื่นผ่านการรองรับ `Rand` / `gen()` ได้อีกต่อไป แต่จะต้องทำผ่าน `SeedableRng::from_rng` ซึ่งรองรับการจัดการข้อผิดพลาดและมีความชัดเจนตรงไปตรงมา

`SeedableRng::reseed` ถูกนำออกไป เนื่องจากไม่ได้มีประโยชน์เพิ่มขึ้นเมื่อเทียบกับ `from_seed` และความได้เปรียบด้านประสิทธิภาพก็ยังไม่มีความชัดเจน

ผู้ที่อิมพลีเมนต์ `SeedableRng` อาจจำเป็นต้องเปลี่ยนประเภท `Seed` ของตนมาเป็นอาร์เรย์ของไบต์ ข้อกำหนดนี้กำหนดขึ้นเพื่อรับประกันความเข้ากันได้ของการจัดการลำดับไบต์ (Endianness) ข้ามแพลตฟอร์ม ทั้งนี้มีฟังก์ชันตัวช่วยใน `rand_core::le` สำหรับอ่านค่า `u32` และ `u64` จากอาร์เรย์ของไบต์ให้ใช้งาน

### PRNG ที่ทำงานเป็นบล็อก

`rand_core` มีเทรตตัวช่วยใหม่ชื่อ `BlockRngCore` และโครงสร้างอิมพลีเมนต์ชื่อ `BlockRng` สิ่งเหล่านี้ออกแบบมาสำหรับตัวสร้างเลขสุ่มที่สร้างข้อมูลสุ่มออกมาทีละบล็อกแทนที่จะเป็นค่าขนาดเวิร์ด (word) การนำเทรตและโครงสร้างนี้ไปใช้มีข้อดี 2 ประการ ได้แก่ มีเมธอดบน `RngCore` ที่ได้รับการปรับแต่งประสิทธิภาพมาให้พร้อมใช้ และสามารถนำ PRNG ดังกล่าวไปใช้งานร่วมกับ `ReseedingRng` ได้โดยมี overhead ที่ต่ำมาก

### RNG สำหรับงานวิทยาการรหัสลับ

มีการเพิ่มเทรตใหม่: `CryptoRng` เทรตนี้เป็น marker trait ล้วนๆ เพื่อระบุว่าตัวสร้างเลขสุ่มตัวใดน่าจะเหมาะสมกับการใช้งานด้านวิทยาการรหัสลับ เช่น
`fn foo<R: Rng + CryptoRng>(rng: &mut R)` *ทั้งนี้ไม่สามารถรับประกันความเหมาะสมต่อการใช้งานเชิงรหัสลับได้อย่างสมบูรณ์*

## การจัดการข้อผิดพลาด

มีการเพิ่มประเภทข้อมูล `Error` ใหม่ ซึ่งออกแบบมาเพื่อรองรับสภาพแวดล้อม no-std โดยเฉพาะ โดยเน้นความเรียบง่ายและมีความยืดหยุ่นเพียงพอสำหรับการใช้งานของเรา (เก็บข้อมูลต้นเหตุหรือ `cause` ไว้ด้วยหากเป็นไปได้):
```rust,noplayground
# extern crate rand_0_5 as rand;
# use rand::ErrorKind;
pub struct Error {
    pub kind: ErrorKind,
    pub msg: &'static str,
    // some fields omitted
}
```
ประเภท `ErrorKind` ที่แนบมาด้วยจะช่วยจัดกลุ่มข้อผิดพลาดในภาพกว้าง ได้แก่ แบบถาวร (permanent), แบบไม่คาดคิด (unexpected), แบบชั่วคราว (transient) และแบบยังไม่พร้อมใช้งาน (not-yet-ready)

รายการฟังก์ชันต่อไปนี้จะใช้งานประเภทข้อผิดพลาดตัวใหม่:

-   `RngCore::try_fill_bytes`
-   `Rng::try_fill`
-   `OsRng::new`
-   `JitterRng::new`

## ตัวสร้างจากภายนอก

เรามีตัวสร้างเลขสุ่มตัวใหม่คือ `EntropyRng` ซึ่งครอบการทำงานของ `OsRng` และ `JitterRng` ไว้ (โดยจะเลือกใช้งานตัวแรกก่อน แต่หากจำเป็นจะสลับไปใช้ตัวหลังเป็นตัวสำรอง) โครงสร้างนี้ช่วยให้สร้าง RNG พร้อมระบบสำรองได้ง่ายผ่าน `SeedableRng::from_rng`
เช่น `IsaacRng::from_rng(EntropyRng::new())?` ซึ่งทำงานเทียบเท่ากับการใช้ `FromEntropy` แตกต่างกันเพียงเรื่องการจัดการข้อผิดพลาด

ขอแนะนำให้เลือกใช้ `EntropyRng` แทน `OsRng` เพื่อป้องกันข้อผิดพลาดบนแพลตฟอร์มที่ตัวสร้างเลขสุ่มของระบบเสียหายหรือใช้การไม่ได้ แต่โปรดระลึกไว้ว่าการสลับไปพึ่งพา `JitterRng` นั้นจะทำงานได้ช้ามาก

## PRNG

*ตัวสร้างเลขสุ่มเทียม* (PRNG หรือตัวสร้างเชิงอัลกอริทึมแบบดีเทอร์มินิสติก) มีการปรับเปลี่ยนหลายประการนับตั้งแต่ 0.4 โดยปัจจุบันได้ย้ายมาอยู่ในโมดูล `prng` (ชื่อเดิมยังคงใช้งานได้ชั่วคราวเพื่อรักษาความเข้ากันได้ย้อนหลัง แต่ท้ายที่สุดแล้วตัวสร้างเหล่านี้มีแนวโน้มจะย้ายออกไปอยู่นอกเครต `rand`)

PRNG ทุกตัวในตอนนี้จะไม่อิมพลีเมนต์ `Copy` เพื่อป้องกันการคัดลอกสถานะของตัวสร้างโดยไม่ตั้งใจ (ซึ่งอาจนำไปสู่การสร้างค่าสุ่มซ้ำเดิม) อย่างไรก็ตาม คุณยังสามารถโคลนสถานะได้อย่างโจ่งแจ้งผ่านเทรต `Clone` นอกจากนี้ PRNG ทุกตัวยังได้รับการปรับแต่งการอิมพลีเมนต์ `Debug` ไม่ให้พิมพ์สถานะภายในออกมา เพื่อป้องกันไม่ให้สถานะของตัวสร้างเชิงรหัสลับรั่วไหลลงไปในไฟล์บันทึก (log files) โดยไม่ได้ตั้งใจ แนะนำให้ผู้พัฒนา PRNG ภายนอกปฏิบัติตามแนวทางนี้เช่นกัน (ดูเพิ่มเติมในเอกสารประกอบของ `RngCore`)

`SmallRng` ถูกเพิ่มเข้ามาเป็นตัวครอบ wrapper โดยในปัจจุบันครอบการทำงานของ `XorShiftRng` ไว้ (และมีแนวโน้มจะเปลี่ยนเป็นอัลกอริทึมอื่นในอนาคตอันใกล้) เหมาะสำหรับการใช้งานที่ต้องการขนาดสถานะที่กะทัดรัดและการเริ่มต้นทำงานที่รวดเร็ว แต่ไม่ต้องการความปลอดภัยระดับวิทยาการรหัสลับ (ประสิทธิภาพการสร้างเลขจริงอาจแตกต่างกันไปตามการทดสอบ benchmark ทั้งนี้ขึ้นอยู่กับลักษณะการใช้งาน มันอาจจะใช่หรือไม่ใช่อัลกอริทึมที่เร็วที่สุด แต่รับรองว่าจะทำงานได้เร็วอย่างสม่ำเสมอ)

### `ReseedingRng`

ตัวครอบ `ReseedingRng` ได้รับการปรับปรุงครั้งใหญ่เพื่อลด overhead ลงอย่างมาก อย่างไรก็ดี `ReseedingRng` แบบใหม่นี้ไม่สามารถทำงานร่วมกับ RNG ได้ทุกตัว แต่จะจำกัดเฉพาะตัวที่อิมพลีเมนต์ `BlockRngCore` เท่านั้น

### ChaCha

เมธอด `ChaChaRng::set_counter` ถูกแทนที่ด้วยเมธอดใหม่ 2 ตัว ได้แก่ `set_word_pos` และ `set_stream` หากจำเป็น คุณสามารถจำลองพฤติกรรมการทำงานของเมธอดเดิมได้ดังนี้:

```rust,noplayground
# extern crate rand_0_5 as rand;
# use rand::prelude::*;
# use rand_chacha_0_1::ChaChaRng;
# fn main() {
let lower = 88293;
let higher = 9300932;

// previously:
// let mut rng = rand::ChaChaRng::new_unseeded();
// rng.set_counter(lower, higher);

// now:
let mut rng = ChaChaRng::from_seed([0u8; 32]);
rng.set_word_pos(lower << 4);
rng.set_stream(higher);

assert_eq!(4060232610, rng.next_u32());
assert_eq!(2786236710, rng.next_u32());
# }
```

### PRNG ตระกูล ISAAC

PRNG `IsaacRng` และ `Isaac64Rng` มีเมธอดสร้างเพิ่มเติมเข้ามาคือ `new_from_u64(seed)` แม้ขนาดสถานะ 64 บิตจะไม่เพียงพอสำหรับงานวิทยาการรหัสลับ แต่ก็มีประโยชน์มากในงานจำลองสถานการณ์ (simulation) และการพัฒนาเกม ในอนาคตเมธอดนี้อาจถูกแทนที่ด้วยเมธอดสร้าง PRNG จากออบเจกต์ใดๆ ที่สามารถแฮชได้

### HC-128

นี่คือตัวสร้างเลขสุ่มเชิงรหัสลับตัวใหม่ ซึ่งได้รับคัดเลือกจาก eSTREAM ให้เป็นหนึ่งใน "สตรีมไซเฟอร์ที่เหมาะสมสำหรับการนำไปใช้อย่างแพร่หลาย" โดยในตอนนี้ HC-128 ได้กลายเป็นตัวสร้างเชิงรหัสลับค่าเริ่มต้นที่ใช้งานโดย `StdRng` และ `thread_rng()`

## ฟังก์ชันและเทรตตัวช่วย

เทรต `Rand` ถูกยกเลิกการใช้งาน (deprecated) โดยแนะนำให้เปลี่ยนมาใช้ `Standard` ซึ่งเป็นการแจกแจงที่แท้จริงและรองรับการสุ่มตัวอย่างได้เหมือนกับ `Rand` ทุกประการ ปัจจุบัน `Rng::gen()` จะเรียกใช้ `Standard` ภายในและยังคงทำงานได้เหมือนเดิมทุกประการ โปรดดูเอกสารประกอบของโมดูล `distributions` สำหรับวิธีอิมพลีเมนต์ `Distribution<T>` ของ `Standard` ให้กับประเภทข้อมูลที่ผู้ใช้กำหนดขึ้นเอง (`T`)

ฟังก์ชัน `weak_rng()` ถูกยกเลิกการใช้งาน ให้เปลี่ยนไปใช้ `SmallRng::from_entropy()` แทน

## การแจกแจง

เทรต `Sample` และ `IndependentSample` ถูกรวมและแทนที่ด้วยเทรตเดียวคือ `Distribution` ซึ่งมีลักษณะเทียบเคียงกับ `IndependentSample` เป็นส่วนใหญ่ เพียงแต่เปลี่ยนจาก `ind_sample` มาเป็นชื่อ `sample` สั้นๆ สำหรับการรองรับการแจกแจงแบบแก้ไขค่าได้ (mutable distributions) นั้นได้ถูกยกเลิกไป แม้ว่าในทางปฏิบัติอาจมีกรณีการใช้งานจริงอยู่บ้าง แต่ก็ไม่ได้แพร่หลายเพียงพอที่จะสนับสนุนให้มีเทรตแยกกันถึงสองตัว หรือบังคับให้ต้องส่งการอ้างอิงแบบมิวเทเบิลไปยังออบเจกต์การแจกแจง ปัจจุบันทั้ง `Sample` และ `IndependentSample` ยังคงเปิดให้เรียกใช้ได้แต่ถูกทำเครื่องหมายเลิกใช้ (deprecated) แล้ว และจะถูกถอดออกในเวอร์ชันถัดไป

ตอนนี้ `Distribution::sample` (รวมถึงอีกหลายฟังก์ชัน) สามารถเรียกใช้งานบน RNG ที่เป็นแบบ unsized (เช่น trait object) ได้โดยตรง

`RandSample` ถูกถอดออกแล้ว (ดูรายละเอียดได้ที่หัวข้อการเลิกใช้ `Rand` และการแจกแจง `Standard` ตัวใหม่)

ตัวครอบ `Closed01` ถูกถอดออก และได้เพิ่ม `OpenClosed01` เข้ามาแทน

### การแจกแจงแบบสม่ำเสมอ

มีการแจกแจงใหม่ 2 แบบ ได้แก่:

-   `Standard` ทำการสุ่มตัวอย่างที่มีการกระจายตัวแบบสม่ำเสมอสำหรับประเภทข้อมูลที่หลากหลาย ทำหน้าที่ทดแทน `Rand`
-   `Alphanumeric` สุ่มตัวอักษร `char` จากช่วง `a-z`, `A-Z`, `0-9`

#### ช่วง

การแจกแจง `Range` ได้รับการปรับปรุงขนานใหญ่และเปลี่ยนชื่อเป็น `Uniform`:

-   `Uniform::new(low, high)` ยังคงมีอยู่ตามเดิม (ช่วงครึ่งเปิด `[low, high)`)
-   `Uniform::new_inclusive(low, high)` เพิ่มเข้ามาใหม่ โดยจะนับรวมขอบเขตบน `high` เข้าไปในผลลัพธ์ด้วย
-   `Uniform::sample_single(low, high, rng)` เป็นทางเลือกที่เร็วกว่าสำหรับการสุ่มเพียงครั้งเดียวจากช่วง `[low, high)`

ปัจจุบันคุณสามารถอิมพลีเมนต์ `Uniform` ให้กับประเภทข้อมูลที่สร้างขึ้นเองได้แล้ว โดยดูรายละเอียดได้ในโมดูล `uniform`

### การแจกแจงแบบไม่สม่ำเสมอ

มีการแจกแจงใหม่เพิ่มเข้ามา 2 แบบ ได้แก่:

-   Poisson จำลองจำนวนเหตุการณ์ที่คาดหวังจากแหล่งที่มีอัตราคงที่ภายในช่วงเวลาคงที่ (เช่น การสลายตัวของนิวเคลียส)
-   Binomial จำลองผลลัพธ์ของการทดลองแบบใช่-ไม่ใช่จำนวนคงที่ครั้ง

อัลกอริทึมการสุ่มตัวอย่างอ้างอิงตามระเบียบวิธีใน "Numerical Recipes in C"

#### การแจกแจงแบบเอกซ์โพเนนเชียลและ Normal

การแจกแจงหลัก `Exp` และ `Normal` ไม่เปลี่ยนแปลง อย่างไรก็ตามเวอร์ชัน "มาตรฐาน" คือ `Exp1` และ `StandardNormal` ไม่ได้เป็นชนิดตัวห่อหุ้มอีกต่อไป แต่เป็นการแจกแจงเต็มรูปแบบ แทนที่จะเขียน `let Exp1(x) = rng.gen();` ตอนนี้คุณเขียน
`let x = rng.sample(Exp1);`
